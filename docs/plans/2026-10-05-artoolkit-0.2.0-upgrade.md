# Plan: barcode support in arjs-plugin-artoolkit + upgrade of AR.js-next and arjs-plugin-threejs

**Goals**

1. Expose barcode markers in arjs-plugin-artoolkit and fix the open bugs (release 0.3.0).
2. Replace AR.js-next's vendored examples with a Vite example that installs packages from npm.
3. Align arjs-plugin-threejs with the 0.2.0/0.3.0 event contract.
4. Bring outdated dev dependencies up to date.

**Decisions (2026-10-05)**

- When `trackBarcode` is called while `detectionMode` has no `matrix` component, the plugin switches to `color_and_matrix` automatically and logs a warning.
- The AR.js-next example consumes the core via `file:../..` and the plugins from npm.
- The examples stay inside AR.js-next.

## Context

- **Plugin 0.2.0 already depends on `@ar-js-org/artoolkit5-ts@^0.3.0`**, which exports:
  - `configureDetector(state, opts)`, with `detectionMode`, `matrixCodeType`, threshold options and `minConfidence: { pattern, barcode }`;
  - `trackBarcodeMarker(state, barcodeId, width)`;
  - `processFrame`, which already returns `type: 'pattern' | 'barcode'`.

  The plugin calls neither of the first two yet.

- **0.2.0 events:**
  - `ar:markerFound` / `ar:markerUpdated`: `{ markerId, type, matrix: Float32Array(16), confidence, vertex, dir, timestamp }`
  - `ar:markerLost`: `{ markerId, type, timestamp }`
  - `ar:getMarker` was removed.
- **Vendored 0.1.x builds:**
  - `AR.js-next/examples/vite-artoolkit/vendor/`
  - `arjs-plugin-threejs/examples/minimal/vendor/`
- **AR.js-next-examples/vite-example** pins plugin 0.1.3 and takes the core from a GitHub commit.

## Phase A: Barcode + fixes in arjs-plugin-artoolkit (→ 0.3.0, no breaking changes)

**API**

```js
new ArtoolkitPlugin({
  wasmUrl,
  cameraParametersUrl,
  detectionMode, // optional, e.g. 'color_and_matrix'
  matrixCodeType, // optional, e.g. '3x3'
  minConfidence, // number (applies to both families) or { pattern, barcode }
  detector: {
    threshold,
    thresholdMode,
    labelingMode,
    imageProcMode,
    patternRatio,
    nearPlane,
    farPlane,
  },
});
await plugin.trackBarcode(barcodeId, (size = 1)); // -> { markerId, type: 'barcode', size }
await plugin.configureDetector(partialOpts); // runtime change; applies only the keys present
```

`loadMarker(patternUrl, size)` is unchanged and remains pattern-only.

**Tasks**

1. **`src/detector/artoolkit-detector.js`:**
   - Add `configure(opts)` and `trackBarcode(id, size)`.
   - Queue the config and the requested barcodes until `ensureReady` completes, then apply the config first and the barcodes after.
   - Re-apply both after a retried state creation.
   - Delegate per-family `minConfidence` to `configureDetector` and remove the local filter.
   - Implement the auto-switch of `detectionMode`.
2. **`src/worker/worker.js`:**
   - Add `configure` → `configureResult` and `trackBarcode` → `trackBarcodeResult`.
   - Forward the detector options in `init`.
   - Move `imageBitmap.close()` into a `finally` block (#28).
3. **`src/plugin.js`:**
   - Add `trackBarcode` and `configureDetector`, using a shared request/timeout helper extracted from `loadMarker`.
   - Normalise `minConfidence`.
   - Close the bitmap on the remaining paths (#28).
   - Count misses per processed frame (#38).
   - Fix the `wasmUrl` JSDoc and make a wasm load failure fail fast (#40).
4. **Tests** (extend the `vi.hoisted` artoolkit5-ts mock with `configureDetector` and `trackBarcodeMarker`):
   - config and barcodes queued before ready are applied once ready;
   - auto-switch of `detectionMode`;
   - `pattern:0` and `barcode:0` coexist as separate markers;
   - events carry `type: 'barcode'`;
   - `minConfidence` given as a number and as an object;
   - partial runtime configure;
   - lost debounce (#38);
   - bitmap close paths (#28);
   - worker message shapes (#29).
5. **Dev example:** a barcode page with a printable 3x3 marker image.
6. **Docs:**
   - README: "Barcode markers" section, and remove "Not yet supported".
   - CHANGELOG entry.
7. **Release:** 0.3.0, published by the user.

## Phase B: npm-based Vite example in AR.js-next

```
examples/vite-artoolkit/
  package.json   # private; deps: "@ar-js-org/ar.js-next": "file:../..", "@ar-js-org/arjs-plugin-artoolkit": "^0.3.0"; dev: vite
  vite.config.js
  index.html
  src/main.js
  public/data/   # camera_para.dat, patt.hiro, barcode marker image
```

1. Import the wasm as `import wasmUrl from '@ar-js-org/artoolkit5-wasm/dist/artoolkit5.wasm?url'`. This needs neither a manual copy nor `vite-plugin-static-copy`.
2. Delete `vendor/` and add `examples/*/node_modules` to `.gitignore`.
3. **`main.js`:**
   - Register the plugin through `pluginManager.register/enable`.
   - Call `loadMarker` and `trackBarcode` once frames flow.
   - Show a HUD with `type:markerId`, the confidence and the vertex overlay.
4. **Core:**
   - Add `EVENTS.MARKER_FOUND/UPDATED/LOST` and `WORKER_READY/ERROR` to `src/core/components.js`.
   - Add a `MarkerEventPayload` typedef.
   - Add `timestamp` to the frame pump's `engine:update` payload.
5. **Docs:** fix the event table in `README.md:117-119`, update `examples/index.html` and the example README.
6. **Optional CI smoke test:** `npm --prefix examples/vite-artoolkit ci && npm --prefix examples/vite-artoolkit run build`.
7. Apply the same update to `AR.js-next-examples/vite-example`.

## Phase C: arjs-plugin-threejs (→ 0.2.0, breaking)

1. **Typed arrays:** accept matrices that pass `ArrayBuffer.isView`. Today `Array.isArray` drops `Float32Array` poses.
2. **Matrix convention:** add `matrixConvention: 'webgl' | 'legacy'`, defaulting to `'webgl'`. The 0.2.0 matrix is already WebGL-ready, so the legacy axis chain must not be applied to it. Verify visually.
3. **Anchors:**
   - Key anchors by `${type}:${markerId}` (#5).
   - Add `getAnchor(id, type = 'pattern')`.
   - `normalizeMarker` reads the new field names first and falls back to the legacy ones.
4. Remove `handleRawGetMarker` and the `ar:getMarker` bridge in the example.
5. Expose `confidence`, `vertex`, `dir` and `type` on `anchor.userData`.
6. Add `MarkerEventPayload` and `MarkerType` to the `.d.ts`.
7. Convert `examples/minimal` to the npm-based layout and add a second object anchored to a barcode.
8. **Tests:**
   - `Float32Array` poses;
   - `pattern:0` and `barcode:0` collision;
   - `markerLost` carrying `type`;
   - legacy payload compatibility.
9. **Docs:** README "Upgrading to 0.2.0" section and peer dependency `@ar-js-org/ar.js-next ^0.2.0`.
